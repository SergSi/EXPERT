# База знаний - экспертная система

## 🎯 Основные возможности

### 📋 Управление базой знаний
- **Автоматическое сканирование** документов из 4-х типов папок:
  - 📖 Нормативные акты (разделение по "ГЛАВА")
  - 📚 Методические материалы (разделение по заголовкам markdown)
  - 🗂️ Структурированные документы (разделение по квадратным скобкам)
  - 👨‍⚖️ Экспертные заключения (сохраняются целиком)
- **Обработка текстов с очисткой от служебной информации** (КонсультантПлюс, ГАРАНТ)
- **Автоматическое определение кодировки** файлов
- **Гибкая конфигурация путей** через JSON файл
- Текстовый файл и файл Markdown (.md) может содержать YAML метаданные в начале файла, которые используются для определения принадлежности раздела к конкретному нормативному документу:
  ```yaml
  ---
  title: Название документа
  ---

### 🎯 Выбор материалов для анализа
- **Поиск и фильтрация** по документам и разделам
- **Пакетный выбор** (выбрать все/снять все)
- **Сохранение выбора** между сессиями
- **Интерактивный интерфейс** с подсветкой выбранных разделов

### 📁 Управление рабочими сессиями
- **Автоматическое создание сессий** с уникальными именами
- **Гибкая система промтов** - поддержка файлов `.txt` и `.md` в корне сессии
- **Экспорт выбранных материалов** в формате JSON
- **Управление вложениями** (поддержка различных форматов файлов)
- **Сохранение ответов** от AI

### 🤖 Подготовка к анализу ИИ
- **Стандартный промт** для экспертных ответов
- **Гибкая система промтов** - можно использовать:
  - Файл `prompt.txt` (создается по умолчанию)
  - Файл `prompt.md` 
  - Любой файл с расширением `.txt` или `.md` (например: `new_prompt.md`, `question.txt`)
- **Автоматическое определение** основного промта (первый найденный файл)
- **Экспорт выбранных разделов** в `materials.json` для использования в промтах

### ⚙️ Администрирование
- **Гибкая настройка** через `config.json`
- **Импорт/экспорт** базы данных (при включенной опции)
- **Проверка целостности** базы данных
- **Детальная статистика** по документам и разделам
- **Управление выбором** (очистка всех выборов)

## 🚀 Установка и запуск

### Требования
- Python 3.8 или выше
- Доступ к интернету для установки зависимостей

После запуска откроется браузер с веб-интерфейсом приложения по адресу: `http://localhost:8501`

## ⚙️ КОНФИГУРАЦИЯ

### Файл конфигурации `config.json`

Приложение использует JSON файл `config.json` для настройки путей к папкам с документами. Файл должен находиться в той же директории, что и `app.py`.

#### Пример файла `config.json`:
```json
{
  "folders": {
    "normative": "./NORMATIVE",
    "methodology": "./METHODOLOGY",
    "structured": "./STRUCTURED",
    "expertise": "./EXPERTISE"
  },
  "database_path": "./knowledge_database.db",
  "sessions_path": "./sessions",
  "default_prompt": "./default_prompt.txt",
  "supported_extensions": [".md", ".txt"],
  "admin_enabled": true,
  "allow_database_export": true,
  "allow_database_import": true,
  "max_upload_size_mb": 100
}
```

#### Параметры конфигурации:
- **`folders`** - пути к папкам с документами разных типов:
  - `normative` - нормативные акты
  - `methodology` - методические материалы
  - `structured` - структурированные документы
  - `expertise` - экспертные заключения
- **`database_path`** - путь к папке с базой данных
- **`sessions_path`** - путь к папке для сохранения рабочих сессий
- **`default_prompt`** - путь к файлу со стандартным промтом
- **`supported_extensions`** - поддерживаемые расширения файлов
- **`admin_enabled`** - включение/выключение администрирования
- **`allow_database_export`** - разрешение на экспорт базы
- **`allow_database_import`** - разрешение на импорт базы
- **`max_upload_size_mb`** - максимальный размер загружаемых файлов

#### Порядок работы с конфигурацией:

1. **Первый запуск**: Если файл `config.json` не существует, приложение создаст его с путями по умолчанию в текущей директории.

2. **Настройка путей**: Отредактируйте файл `config.json` в любом текстовом редакторе, указав актуальные пути к вашим папкам с документами.

3. **Проверка доступности**: Во вкладке "Настройки" можно проверить доступность всех папок.

4. **Скачивание/загрузка**: Текущую конфигурацию можно скачать во вкладке "Настройки" для редактирования или сохранения резервной копии.

## 🚀 Этапы полного цикла экспертизы

### **📋 Этап 1: Импорт документов**
1. **Получение исходных материалов** от заказчика
2. **Сортировка документов** по типам:
   - Нормативные акты → папка `NORMATIVE`
   - Методические материалы → папка `METHODOLOGY`
   - Структурированные данные → папка `STRUCTURED`
   - Предыдущие экспертизы → папка `EXPERTISE`
3. **Проверка форматов файлов** (поддержка: .md, .txt)
4. **Внесение YAML-метаданных** в начало документов при необходимости

### **🔍 Этап 2: Индексирование**
1. **Запуск сканирования папок** через веб-интерфейс (вкладка "Администрирование" или боковая панель)
2. **Автоматическое разбиение документов** на разделы:
   - Нормативные акты → по главам
   - Методические материалы → по заголовкам markdown
   - Структурированные документы → по квадратным скобкам
   - Экспертные заключения → целиком
3. **Очистка текста** от служебных комментариев КонсультантПлюс и ГАРАНТ
4. **Извлечение метаданных** из YAML-заголовков
5. **Обновление статистики базы** (количество документов, разделов, слов)

### **🎯 Этап 3: Селекция материалов**
1. **Переход во вкладку "Выбор разделов"** в веб-интерфейсе
2. **Применение фильтров** для поиска релевантных материалов:
   - Поиск по тексту в названиях документов и разделов
   - Фильтр по конкретным документам
3. **Выбор разделов** путем установки флажков в чекбоксах
4. **Сохранение выбора** в базу данных

### **📁 Этап 4: Создание рабочей сессии**
1. **Переход во вкладку "Рабочие сессии"**
2. **Создание новой сессии**:
   - Автоматическое имя (session_YYYYMMDD_HHMMSS)
   - Или указание собственного имени
3. **Выбор активной сессии** для работы
4. **Экспорт выбранных материалов** в сессию

### **🤖 Этап 5: Настройка промта и подготовка к анализу**
1. **Работа с промтом** (гибкие варианты):
   - **Вариант A**: Редактирование существующего `prompt.txt`
   - **Вариант B**: Создание нового файла промта (например: `question.md`, `new_prompt.txt`)
   - **Вариант C**: Использование нескольких файлов промтов - система выберет первый найденный
2. **Добавление вложений** (если необходимо):
   - Поместить файлы в папку `attachments/` сессии
   - Поддерживаемые форматы: PDF, JPG, PNG, DOCX, XLSX, TXT
3. **Проверка структуры сессии**:
   - Промт-файл(ы) (.txt или .md)
   - Файл `materials.json` с выбранными разделами
   - Папка `attachments/` с дополнительными файлами

### **🧠 Этап 6: Анализ ИИ**
1. **Открытие файлов сессии** (или папки сессии целиком)
2. **Использование промта** одним из способов:
   - Копирование содержимого основного промт-файла
   - Прикрепление всех файлов сессии к ИИ-системе
3. **Получение ответа** от ИИ-ассистента (DeepSeek или другой)
4. **Анализ ответа** на соответствие требованиям:
   - Все утверждения основаны на предоставленных материалах
   - Указаны пробелы в информации при их наличии
   - Структура соответствует стандартному промту
   - Даны практические рекомендации
5. **При необходимости — итерационная работа** с ИИ (уточнения, дополнения)

### **📄 Этап 7: Документирование и сохранение**
1. **Сохранение ответа AI** в файл `response.md` в папке сессии
2. **Форматирование ответа** в соответствии с корпоративными стандартами
3. **Архивация сессии** для дальнейшего использования
4. **Добавление экспертного заключения** в папку `EXPERTISE` для будущего использования

### **✅ Завершение цикла**
1. **Сохранение всех файлов сессии** в архиве
2. **Запись статистики работы** (время выполнения, объем материалов)
3. **Контроль качества** — финальная проверка:
   - Полнота ответа на исходный запрос
   - Соответствие нормативным требованиям
   - Качество оформления
   - Отсутствие противоречий
4. **Передача результата** заказчику
5. **Очистка выборов** в базе для следующей задачи

## 💡 Советы по работе

### Для настройки путей:
1. **Используйте абсолютные пути** в `config.json` для надежности
2. **Для Windows**: используйте двойные обратные слэши `\\` или обычные слэши `/`
3. **Проверяйте доступность** папок через интерфейс перед сканированием
4. **Создавайте резервные копии** `config.json` отдельно от проекта

### Для работы с документами:
1. **Группируйте документы** по темам в соответствующих папках
2. **Используйте фильтры** для быстрого поиска нужных материалов
3. **Сохраняйте выбор** перед созданием сессии
4. **Экспериментируйте с промтами** для разных типов задач

### Для работы с сессиями:
1. **Создавайте отдельную сессию** для каждой экспертной задачи
2. **Используйте понятные имена** сессий при ручном указании
3. **Экспортируйте материалы** только после окончательного выбора разделов
4. **Архивируйте завершенные сессии** для архива

### Для работы с промтами:
1. **Начните с `prompt.txt`** - стандартный промт уже содержит оптимальную структуру
2. **Создавайте специализированные промты** для разных типов задач:
   - `legal_analysis.md` - для юридического анализа
   - `technical_review.txt` - для технических обзоров
   - `brief_answer.md` - для кратких ответов
3. **Система автоматически выберет** первый найденный файл промта
4. **Сохраняйте успешные промты** как шаблоны для будущих задач

### Для работы в команде:
1. **Не коммитьте `config.json`** в репозиторий
2. **Создайте `config.example.json`** с примером структуры
3. **Используйте разные конфигурации** для разных рабочих окружений
4. **Синхронизируйте папки с документами** между членами команды

## ⚠️ Устранение неполадок

### Если приложение не запускается:
```bash
# Проверьте установку зависимостей
pip list | grep -E "streamlit|pandas|yaml|chardet"

# Переустановите зависимости
pip install --force-reinstall streamlit pandas pyyaml chardet
```

### Если не находятся документы:
1. **Проверьте `config.json`** - правильность путей
2. **Проверьте доступность** папок во вкладке "Настройки"
3. **Убедитесь**, что файлы имеют расширения `.md` или `.txt`
4. **Проверьте права доступа** к папкам

### Если не работает конфигурация:
1. **Удалите `config.json`** и создайте новый через интерфейс
2. **Проверьте синтаксис JSON** - можно использовать онлайн валидатор
3. **Перезапустите приложение** после изменения конфигурации

### Если не создаются сессии:
1. **Проверьте права на запись** в папку `sessions/`
2. **Убедитесь**, что нет конфликта имен сессий
3. **Проверьте свободное место** на диске

## 📋 Поддерживаемые форматы документов

Приложение поддерживает два формата документов:

### 1. 📝 Markdown (`.md`)
- **Рекомендуемый формат**
- Поддерживает структурирование заголовками (`#`, `##`)
- Может содержать YAML метаданные
- Хорошая читаемость и структурированность

### 2. 📄 Текстовые файлы (`.txt`)
- Простой текстовый формат
- Автоматическое определение кодировки (UTF-8, Windows-1251, KOI8-R и др.)
- Поддерживает разделение по правилам для каждой папки
