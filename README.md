# Экспертная система для работы с документами

Система для выбора и экспорта разделов нормативных, методических и структурированных документов.

## Возможности

- Чтение документов из четырёх типов папок (NORMATIVE, METHODOLOGY, STRUCTURED, EXPERTISE)
- Автоматическое распознавание глав и статей в нормативных документах
- Поддержка диапазонов статей (например, `1-10`) и составных номеров (например, `39.36-1`)
- Разбиение структурированных документов по заголовкам в квадратных скобках `[Заголовок]`
- Создание наборов документов с выбором конкретных глав, статей или разделов
- Визуальный выбор наборов через веб-интерфейс
- Экспорт выбранных материалов в JSON-файл
- Встроенный редактор файла наборов `sets.json`

## Правила разметки файлов по папкам

### 📁 NORMATIVE (Нормативные документы)

**Назначение:** законы, кодексы, постановления, приказы

**Особенности обработки:**
- Документы автоматически разбиваются на **главы** (по умолчанию)
- Поддерживается разбиение на **статьи** с фильтрацией через `sets.json`
- Поддерживаются диапазоны статей: `1-5`, `10-20`
- Поддерживаются составные номера статей: `39.36`, `39.36-1`, `15.2`

**Формат заголовков глав:**
```
Глава 1. Общие положения
ГЛАВА 2. Права и обязанности
Глава 6.1. Особенности регулирования
```

**Формат статей:**
```
Статья 1. Основные понятия
Статья 39.36-1. Особенности образования земельных участков
```

**Пример документа:**
```markdown
# ЗЕМЕЛЬНЫЙ КОДЕКС РОССИЙСКОЙ ФЕДЕРАЦИИ

## Глава 1. Общие положения

**Статья 1. Основные принципы земельного законодательства**
1. Учет значения земли как основы жизни и деятельности человека...
2. Приоритет охраны земли как важнейшего компонента окружающей среды...

**Статья 2. Земельное законодательство**
1. Земельное законодательство состоит из настоящего Кодекса...
2. Нормы земельного права, содержащиеся в других федеральных законах...

## Глава 2. Охрана земель

**Статья 12. Цели охраны земель**
1. Охрана земель осуществляется в целях...
```

### 📁 METHODOLOGY (Методические документы)

**Назначение:** методики, инструкции, рекомендации

**Особенности обработки:**
- Документы сохраняются **целиком** (не разбиваются)
- Подходит для методических указаний и инструкций

**Пример документа:**
```markdown
# Методика определения кадастровой стоимости

## 1. Общие положения

Настоящая методика устанавливает порядок определения кадастровой стоимости...

## 2. Порядок расчета

Расчет кадастровой стоимости осуществляется по формуле...
```

### 📁 STRUCTURED (Структурированные документы)

**Назначение:** документы с четкой вложенной структурой

**Особенности обработки:**
- Разбиение по **заголовкам в квадратных скобках** `[Заголовок]`
- Идеально для технической документации и регламентов

**Формат заголовков:**
```
[Раздел 1. Общие положения]
Текст раздела...

[Раздел 2. Требования к документам]
Текст раздела...
```

**Пример документа:**
```markdown
[1. Общие положения]
1.1. Настоящий регламент определяет порядок...
1.2. Услуга предоставляется на безвозмездной основе...

[2. Порядок подачи заявления]
2.1. Заявление подается в электронном виде...
2.2. Срок рассмотрения - 10 рабочих дней...
```

### 📁 EXPERTISE (Экспертные заключения)

**Назначение:** экспертные заключения, решения, акты

**Особенности обработки:**
- Документы сохраняются **целиком**
- Подходит для готовых экспертных мнений

**Пример документа:**
```markdown
# Экспертное заключение №123

## Вопрос 1: О правомерности отказа в предоставлении участка

**Ответ:** Отказ является неправомерным, так как...

## Выводы

На основании анализа нормативной базы...
```

## Формат файла наборов (sets.json)

Файл `sets.json` определяет, какие документы и какие их части должны быть экспортированы.

### Структура файла:

```json
[
    {
        "id": "unique_set_id",
        "name": "Название набора",
        "description": "Описание набора (необязательно)",
        "selected": true,
        "items": [
            {
                "type": "normative",
                "document": "Земельный кодекс РФ.txt",
                "chapters": ["Глава 1", "Глава 2"],
                "articles": ["1", "2", "5-10", "39.36-1"]
            },
            {
                "type": "structured",
                "document": "Порядок действий.md",
                "sections": ["[Раздел 1]", "[Раздел 2]"]
            },
            {
                "type": "methodology",
                "document": "Методика расчета.md"
            },
            {
                "type": "expertise",
                "document": "Заключение эксперта.md"
            }
        ]
    }
]
```

### Параметры для разных типов документов:

| Тип           | Обязательные поля  | Опциональные поля                                            |
| ------------- | ------------------ | ------------------------------------------------------------ |
| `normative`   | `type`, `document` | `chapters` (список глав), `articles` (список статей или диапазонов) |
| `structured`  | `type`, `document` | `sections` (список заголовков в квадратных скобках)          |
| `methodology` | `type`, `document` | —                                                            |
| `expertise`   | `type`, `document` | —                                                            |

### Правила для нормативных документов:

- Если не указаны ни `chapters`, ни `articles` — выводится **весь документ целиком**
- Если указаны `chapters` — выводятся **все статьи из этих глав**
- Если указаны `articles` — выводятся только указанные статьи
- Если указаны и `chapters`, и `articles` — выводятся и то, и другое

### Форматы указания статей:
- Одна статья: `"1"`
- Составная статья: `"39.36-1"`
- Диапазон статей: `"1-10"`

## Работа с программой

### 1. Подготовка документов

Поместите файлы `.md` или `.txt` в соответствующие папки:
- `NORMATIVE/` — законы, кодексы
- `METHODOLOGY/` — методические документы
- `STRUCTURED/` — документы с разделами в квадратных скобках
- `EXPERTISE/` — экспертные заключения

### 2. Создание наборов

Создайте файл `sets.json` в корне проекта (или используйте кнопку "Создать пример" в интерфейсе).

Пример набора для Земельного кодекса:
```json
{
    "id": "zk_rf_articles",
    "name": "Земельный кодекс РФ - основные статьи",
    "description": "Ключевые статьи Земельного кодекса",
    "selected": true,
    "items": [
        {
            "type": "normative",
            "document": "ЗК РФ.txt",
            "articles": ["1", "11.2", "11.3", "39.3", "39.36-1", "60"]
        }
    ]
}
```

### 3. Запуск программы

```bash
streamlit run app.py
```

### 4. Выбор наборов

В интерфейсе отметьте нужные наборы галочками.

### 5. Генерация экспорта

Нажмите кнопку **"Сгенерировать выходной файл"** в боковой панели.

### 6. Получение результата

Файл сохраняется в папку `data/` с именем `export_YYYYMMDD_HHMMSS.json`

## Устранение проблем

### Ошибка "Python не найден"

Установите Python с [python.org](https://python.org) и добавьте его в PATH при установке.

### Ошибка при активации venv

Выполните в PowerShell:
```bash
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### Ошибка валидации sets.json

Программа показывает ошибки в боковой панели. Основные причины:
- Отсутствуют обязательные поля (`id`, `name`, `items`)
- Недопустимое значение `type` (допустимые: `normative`, `structured`, `methodology`, `expertise`)
- Неуникальный `id`
- Неверный формат диапазона статей (должен быть `X-Y`)

### Документы не отображаются

Убедитесь, что:
- Файлы имеют расширение `.md` или `.txt`
- Файлы находятся в правильных папках (`NORMATIVE/`, `METHODOLOGY/`, `STRUCTURED/`, `EXPERTISE/`)
- В названиях файлов нет недопустимых символов
